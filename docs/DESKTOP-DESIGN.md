## 現状から引き継ぐもの
実装の基準は `web/src/App.tsx`、`AssetDetail.tsx`、`ArchiveDialog.tsx`、`styles.css`。React/TypeScriptの画面を両OSで共有し、Web版の改善を同時に反映する。既存SwiftUI iOS版は独立して保持する。

- クリーム色の背景、緑のアクセント、左サイドバー、検索と追加の導線。
- 正方形の密な素材一覧、画像下部の半透明タイトル帯、10pxの1行タイトル。一覧にタグを出さず詳細・検索で扱う。列数は現行CSSの幅別設定を継承する。
- 一覧設定ダイアログ、詳細、タグ・メモ・コレクション・お気に入り、複数選択、一括整理、原本/ZIP取得、ごみ箱・復元・完全削除。
- 通常／アーカイブの切り替え。コードにはarchivedAtと操作が存在するが、S3保存クラス変更は未実装。ローカルでのアーカイブを容量削減成功と表示しない。

初期ウィンドウは1280×900、最小幅900を候補とし、狭幅や拡大時は既存レスポンシブへ追従する。OS標準タイトルバーを使い、素材のドラッグ領域とウィンドウ移動領域を混ぜない。サイズは実機評価で調整する。

## 構成案と選定ゲート
第一候補はElectronの共通シェルと既存Python APIの子プロセス。既存Chromium系UIとAPIの変更を小さく保ち、両OSの同じ画面を評価する。Windows試作にElectronを追加した。採用確定は下記D1の残る実機・配布評価後。

```text
Electron main → Python API起動・監視・終了 / OSダイアログ・保存
      ↓ 最小限のpreload bridge
共有React UI → 同一origin /api/v1 → Vault → SQLite / objects / staging
```

PythonはNode用utilityProcessではなく管理対象の子プロセスとして起動する。配布時はOS/CPU別Python実行環境と依存を同梱する案を試験し、利用者によるPython/Nodeインストールを不要にする。Pythonのパッケージ方式は起動・署名試験で選ぶ。

| 候補 | 利点 | このプロジェクトでの検証点 |
| --- | --- | --- |
| Electron（第一候補） | React UIとブラウザ挙動を共有しやすい | Chromium＋Pythonの配布容量・メモリ・起動時間 |
| Tauri | 軽量なシェルの候補 | OS別WebView差、RustとPythonの配布・通信管理 |
| SwiftUI＋Windows個別UI | OS固有操作に合わせやすい | 同じ素材UIと整理操作を二重実装する負担 |

## APIと起動・終了の境界
現APIは固定8765/5173のorigin、リポジトリ下のデータ、Web相対URLを前提とする。アプリ化では以下を専用設定として追加する。現Webの開発起動は維持する。

1. single-instanceとライブラリ単位の排他を確保し、同じDBを別プロセスが操作しない。Web版のDBを暗黙に開かない。
2. APIを127.0.0.1の空きポートへbindする。起動結果を専用通信でmainへ通知し、ランダムな起動トークンと期待するライブラリIDで本人プロセスを確認する。既存ポートの応答だけで成功判定しない。
3. APIからWebビルドを同一originで配信し、相対URLを維持する。デスクトップ専用origin/Host検証とトークン検証を追加する。トークンはmain側の通信介入でAPI要求へ付け、URL・ログ・ディスクへ記録しない。画像・ダウンロードにも適用する。
4. API準備完了まで起動画面。タイムアウト・クラッシュでは原因と再起動導線を表示する。素材更新のPOSTは通信失敗後に自動再送せず、状態確認して再試行する。
5. 終了時は新規追加を止め、処理完了を待ってAPIを停止する。中断を選ぶ場合もstagingを保持する。強制終了後は既存recoverを利用し、原本・関連DB整合性をテストする。
6. Macのウィンドウを閉じる操作とQuitを区別する。初期版はトレイ常駐なし。APIはアプリ終了時に停止し、起動失敗時も所有する子プロセスを回収する。

## OS連携と保存
次期のディレクトリ参照・原本所在・リモート移動・キャッシュ管理は[保管設計](STORAGE-DESIGN.md)に従う。以下のコピー取り込みと独立保存は現在の試作の動作で、既存データを保持して段階移行する。

| 操作 | macOS | Windows |
| --- | --- | --- |
| ファイル追加 | 標準Openダイアログ、Finderドロップ | 標準Openダイアログ、Explorerドロップ |
| 原本・ZIP保存 | Saveダイアログ | Saveダイアログ |
| メニュー | アプリ/ファイル/編集/表示、Cmd修飾 | ファイル/編集/表示、Ctrl修飾 |
| 検索・追加 | Cmd+F / Cmd+O | Ctrl+F / Ctrl+O |
| 設定・終了 | Cmd+, / Cmd+Q | メニュー設定 / Alt+F4 |
| 標準データ候補 | Application Support配下 | LocalAppData配下 |

内部識別名はphoto-hub、製品表示名は未決定。ElectronのuserData配下に設定、OS別のローカルデータ領域にライブラリを分ける。実際の絶対パスを設定画面に表示する。インストール先、作業ディレクトリ、一時領域には原本を置かない。

ファイル選択はコピー取り込み。元ファイルを移動・削除しない。フォルダ選択は件数と合計サイズを確認してから追加し、初期版では常時監視・シンボリックリンクの再帰追跡を行わない。現APIの100MB/原本、500MB/要求、100件/バッチ、ZIP合計1GBを維持し、超過時は明示する。

保存は一時ファイルから完了後に確定し、既存ファイルの上書きはOSダイアログで確認する。ZIPを全量ブラウザBlobへ載せる現経路は、大容量対応時にmain側のストリーム保存へ切り替える。

バックアップは取り込み・編集を停止してAPIを終了後、DB・objects・stagingを含むライブラリ全体をコピーする。復元は現ライブラリを退避し、件数・ハッシュを検証後に切り替える。初期版は移行ウィザードを別工程とし、既存 `.local/asset-library` を自動移動しない。MacとWindowsはそれぞれ独立したライブラリで、同期は別工程。

## 権限と配布
rendererはnodeIntegration無効、contextIsolationとsandbox有効。preloadは型付きの追加・保存・設定操作だけ公開し、任意パス読み書き・任意コマンド実行を公開しない。mainはIPC送信元、入力、選択対象を検証する。外部ページ遷移・新規ウィンドウを拒否し、許可したhttpsリンクだけ標準ブラウザへ渡す。CSPを設定し、ファイル名・メモをHTMLとして挿入しない。[Electron Security](https://www.electronjs.org/docs/latest/tutorial/security/)

初期配布はストア外の試用。Windows x64を先に検証し、Mac arm64、Intel Macは必要性を確認して別ビルドとする。macOSはDeveloper ID署名・公証、Windowsは署名とインストーラーの実機試験を配布ゲートとする。同梱Pythonも署名対象を確認する。自動更新は初期範囲外とし、データを保持した手動更新・旧版復帰の制約を確認する。[Code Signing](https://www.electronjs.org/docs/latest/tutorial/code-signing)、[Distribution](https://www.electronjs.org/docs/latest/tutorial/distribution-overview)

## 未確定事項
正式名、対象OS最低バージョン、Intel Mac対応、配布形態は試用対象に合わせて決める。写真ライブラリ直接連携・HEICデコード・クラウド同期・AI・フォルダ監視は別工程。初期版の必須条件は現Web UIの操作を維持し、端末内の原本を保全すること。

確認用の明示的な --web-library 起動では停止中のWebライブラリをそのまま使う。原本をコピーせず所在の混在を評価する。既定の独立ライブラリは維持し、同じDBの同時運用は対象外。
