# 送信時の内容重複チェック

通常送信と暗号化送信は、それぞれ独立して、原本のSHA-256とバイト数で同じ内容を判定する。ファイル名・拡張子・元の保存場所に依存しない。同じ画像でも再圧縮やメタデータの変更で原本のバイト列が違えば別素材になる。通常と暗号化の間では判定せず、暗号化は同じ鍵IDの領域内で判定する。

## 判定と表示

確認・準備はローカルのみ。送信直前と履歴からの再開時にS3のカタログを全ページ取得する。通常は過去の保存完了分を含む全カタログ、暗号化は同じ鍵IDの全カタログを比較する。同時選択内のコピー、別フォルダの予約送信も対象。先の予約が保存完了した後、次の予約で改めて比較する。

一致候補のS3原本の存在・サイズを確認し、通常はSHA-256（分割時は合成値）も照合する。原本がなくなっていれば重複扱いにしない。管理情報の取得・検証・暗号化一覧の復号に失敗した場合は、重複チェックを省略して送らず停止する。

履歴には「内容が同じN件は送信しません」と表示する。重複分の原本・小画像は送信せず、新しい場所への別名の登録もしない。重複だけならカタログも作らず、既存のフォルダ表示を維持する。新規分がある通常送信では、同じrootの最新保存済み素材を一覧へ引き継ぎ、新規・内容変更分を追加する。元フォルダから消えた素材も自動削除しない。Macの元ファイルは変更・削除しない。

通常のごみ箱にある原本も、完全削除前で存在する間は重複扱いになる。必要ならごみ箱から復元する。完全削除済みは対象外。既にある重複ファイルの自動統合・削除は行わない。

## 暗号化と保持

暗号化カタログは同梱helperで認証・復号し、比較用の平文はメモリ内だけで扱う。S3に原本ハッシュの平文索引を追加せず、既存のランダムIDの保存キーと暗号方式を維持する。鍵は匿名stdinだけでhelperへ渡す。取得する一時ファイルは暗号文で、終了時・次回起動時に整理する。

送信計画には既存と同様に原本ハッシュを保持する。今回除外した候補も非公開のローカル履歴に保持し、途中再開で保存先を再確認する。鍵・平文の復号カタログを履歴へ追加しない。

## 検証と制限

`local-api/tests/test_upload_duplicates.py` は模擬S3と実暗号化helperで、改名・移動・同時選択・履歴なし・予約順・途中再開・混在追加・ごみ箱・原本欠損・鍵別領域・改ざん拒否・ページングを確認する。分割再開は `test_upload_improvements.py` でも確認する。

確定したカタログがない未完了送信は全体比較の対象外。同じ履歴を再開すれば既存送信の照合を行う。複数Macから同時に同内容を送る場合の排他制御はない。現在のMacアプリ内では送信予約を順番に実行する。一覧取得と一致候補のHEADの通信が追加される。実AWSでの速度・料金・実素材の操作は別途確認する。

## 検査の通信量制限（2026-10-15）

毎回S3の一覧とHEADで現在の版・ETag・サイズを確認し、保存先（バケット・プロファイル・リージョン）と鍵IDが同じで、版・ETag・サイズが変わらない管理情報だけをメモリから再利用する。通常・暗号化それぞれ最大64MiBのLRU。再起動で破棄し、暗号化のキャッシュは暗号文だけ。キャッシュ利用時も毎回復号・検証するので、違う鍵・改ざん・ごみ箱更新を無視しない。原本の存在と照合は省略せず、同一検査中に確認済みの同じ内容は重複HEADを省く。

1検査は管理情報2,000件、新たに要求する管理情報の本文合計64MiBまで。LISTはCLIの自動全件取得を止め、1ページ1,000件ずつ処理する。上限を超える場合は原本・小画像・新カタログを送る前に停止する。確認を省略した送信や履歴の自動削除はしない。上限に達した場合は、履歴を削除せず索引の改善を検討する。64MiBは要求予定量であり、CLI内部再試行・エラー応答・通信途中の重複受信まで含む厳密な回線量上限や月額制限ではない。
