# 軽量な動画配信の調査

2026-10-14。原本は非公開S3で保持し、Macで手動送信、iPhoneは閲覧専用。最初の候補は原本＋再生用MP4を1種類。複数画質HLS・CDN・AWS動画変換はまだ追加しない。

## 調査

`scripts/audit-video-storage.py` にMacの動画ファイルまたはフォルダを指定する。ffprobeでローカル読み取りのみ。変換・S3取得・送信・削除を行わず、出力に名前・パス・署名URLを含めない。iCloudファイルはOSによる取得待ちになる場合がある。解析できなかった動画は未計測件数に含め、計算から除外したことを明示する。

```sh
.venv/bin/python scripts/audit-video-storage.py '/動画ファイルまたはフォルダの絶対パス'
```

音声込み2・3・5Mbpsと月1・10・30時間視聴を比較。これは仮定で、選定済み画質ではない。長さ×Mbps×10^6÷8のbytesに10%の計画上の余裕を加える。実際の先読み・シーク・再取得は増減する。保存量は全動画時間、通信量は視聴時間で別計算する。VBRの実容量は変換後に確認する。

## 費用・判定

1GiB=2^30 bytes。2026-10-14確認の東京S3 Standard $0.025/請求GB月、インターネット転送$0.114/請求GBを仮定。計算ではbinary GBに換算。無料枠を控除しない。為替150円/USDと税10%を別の仮定として使用。公式出典と付帯サービスは [S3閲覧設計](S3-READER.md) を参照。原本保存・API・GET/PUT・ログ・旧版はこのツールの派生比較に含まず、総額見積もりで加算する。

月間効果=原本での転送費−軽量版の転送費−軽量版の保存費。元から低ビットレートなら悪化する。ライブラリ平均のビットレートは個々の視聴頻度を反映しないため目安。実利用による確認が必要。無料転送枠が余る場合は通信費削減が生じず、追加保存費だけ増える場合もある。

## 次段階の候補と承認

軽量MP4はH.264/AAC、720pまたは1080p、アップスケールなし、先頭に再生索引を置くfaststartを候補とする。HDR・高フレームレート・縦動画・音声・文字の可読性は個別確認。画質を勝手に固定せず、サンプルとMac処理時間・一時容量を確認して選ぶ。常時同期はしない。

原本と派生の容量を合算し、旧版・一時ファイル・中断送信も予算に含める。原本への上書き・削除はしない。派生は独立キーとカタログ参照、認証後のGETのみ許可を設計してから追加。軽量版を標準、原画質を明示選択する案。変換設定、対象、追加保存量、S3への送信を具体的に提示して承認後に実行。Mac内の手動変換は実装済み。軽量版の別フォルダへの手動送信は実装済み。同じ素材内でのiOS画質選択は未実装。

## Macの手動作成画面

上部「軽量版を作る」→「動画を選ぶ」→内容・見込み容量を確認→「軽量版を作る（Mac内）」。パラメーター入力は不要。1080pまで、アップスケールなし、縦動画の向きを保った範囲で縮小、元fpsを60fpsまで維持、H.264/AAC・音声込み約3Mbps目標・faststart。1本5GiB、2時間以内。HDRと60fps超は保留して拒否する。元から軽い動画は容量増加の注意を表示する。

進捗・停止・手動再試行・作成履歴・再生・取り出しがある。Macを終了すると作成を停止し、再起動時は自動再開しない。途中の作業MP4だけを片付け、原本・完成済み結果は削除しない。作成結果はアプリデータ内 `light-videos/{ID}/light.mp4`、原本ライブラリではなく派生作業領域。ディレクトリ0700、結果・管理JSON0600。未変更の同じ原本は作成前／作成中／完成の履歴を再利用する。取り出し時の追加コピーを含め、Macの容量を使う。S3への自動送信はない。

GET一覧、POST inspect、POST {ID}/start・cancel、GET {ID}/contentはローカル `/api/v1/light-videos` のみ。AWS権限・リソースは追加しない。再生はRange対応、private/no-store。作業開始前に出力見込み2倍＋256MiBの空きを確認し、出力にサイズ上限を設ける。他アプリによるディスク消費まで保証する制限ではない。完成後の容量は実測値、目安は音声込み3Mbps×長さ＋10%。

## ローカル比較サンプル

2026-10-14、ユーザー承認で指定動画の60秒地点から30秒をローカル変換。1080p/60fps、H.264、動画目標2872kbps＋AAC128kbps、faststart。軽量版11,482,864 bytes／30秒／実測3.062Mbps。原画質の再エンコードなし切り出しは49,451,066 bytes／30.083秒で、キーフレーム境界により区間長が僅かに異なる。サンプル同士で約77%減。全編・別動画で同じ効果を保証しない。

作業約16.2秒、出力合計約60.9MB。Git対象外の `.local/video-samples/2026-10-14/` に保存し、ディレクトリ0700・動画0600。原本の前後SHA-256一致、両サンプル全編デコード成功、索引が本体より前にあることを確認。S3送信なし。実際の画質・可読性は本人確認待ち。全編変換・アップロード設定の承認には流用しない。

## 軽量版のS3送信

作成完了後「S3へアップロード · 内容を確認」→保存先・容量・追加保存料を確認→送信のチェック→「アップロードを開始」。確認の準備段階ではAWSへアクセスしない。保存先はこのMacの直近アップロード設定を使う。設定履歴がなければ先にフォルダアップロードで設定する。

軽量版だけを独立した「元の名前（軽量版）」フォルダの1素材として保存。元動画は送信・上書き・削除しない。生成用JSON・Macパスは送らない。既存のmedia-hub/originals/{別assetID}/{SHA256}を独立メディアの保管キーとして使い、既存カタログへ新しい別rootで登録する。名前に軽量版を明示し、元動画と同一のassetID・rootIDに統合しない。既存の本人GET権限・非公開S3・SSE-S3・TLSを再利用し、AWSリソース／権限変更は不要。判断は [0013](../decisions/0013-light-video-separate-catalog.md)。

既存アップローダーの条件付きPUT・SHA256／容量照合・版固定・中断／手動再試行を使用する。同じ生成結果と保存先の送信計画は再利用。軽量版の変更時や余計な素材が作業領域にある場合は準備を拒否する。送信後はiPhoneの一覧を更新して別フォルダから開く。実iPhoneからの新規軽量素材再生は未確認。軽量版へ自動切替はしない。

追加保存料は実際の生成容量÷2^30×$0.025×為替×税。原本・旧版・管理JSON・PUT/HEAD・閲覧転送・API等は別加算。2026-10-14の東京単価と150円/USD・税10%の仮定を確認画面に表示。自動送信・自動削除・原本の画質変更はない。今回の実装検証では模擬S3のみを使い、個人メディアはAWSへ送っていない。
