# 段階7: 実機検証チェックリスト

シミュレータと自動テストの結果はsessionsへ記録する。本書の項目は実機で実施した時だけチェックする。

## 取り込みと表示
- [ ] JPEG/HEIC/PNGを各1枚以上、複数選択して取り込む。
- [ ] 限定アクセス、拒否、iCloud原本未ダウンロードで説明・再試行が機能する。
- [ ] 編集済み写真でも原本のバイト列を保存し、画素数・撮影日時を確認する。
- [ ] 同じ資産の再取込と別資産の同一バイト列の重複を防ぐ。
- [ ] 位置情報や向きのある画像、横長/縦長で派生の表示を確認する。
- [ ] 拡大・縮小、左右スワイプ、端末回転、VoiceOverで操作する。

## 保存と中断
- [ ] ローカル開発モードで全3オブジェクト照合後だけ完了になる。
- [ ] AWS未設定で本番モードを選ぶと明示的に失敗し、未保存原本を保持する。
- [ ] 実AWSでログイン、3オブジェクトPUT/HEAD、期限切れURL再発行を確認する。
- [ ] 機内モード、アプリ強制終了、再起動後に未完了を再試行する。
- [ ] 保存確認前は端末内コピーを解放しない。保存後はS3から再閲覧できる。
- [ ] 容量不足で取り込み・派生生成・ダウンロード・SQLite書込の失敗を表示し、既存データを保持する。

## フォルダ同期（AWS保留中の優先確認）
- [ ] 設定からiCloud Driveのフォルダを選び、一覧・詳細に表示する。
- [ ] 再起動後も同じフォルダへアクセスできる。
- [ ] iCloud取得待ちから再同期で表示でき、オフライン時は保存済みプレビューを表示する。
- [ ] 改名・移動で整理情報を維持し、変更・欠損を通知する。
- [ ] フォルダ再指定で復旧し、アプリ内削除でフォルダ原本を削除しない。

仕様と制限は [iOSフォルダ同期](IOS-FOLDER-SYNC.md)。

## 整理・削除・復元
- [ ] アルバム作成、追加・取り外し、お気に入りが再起動後に残る。
- [ ] 原本を写真ライブラリに保存し、元形式とサイズを確認する。
- [ ] 削除確認をキャンセルすると何も消えない。
- [ ] 通信中断の削除はdeletingとして残り、再試行で完了する。
- [ ] AWS削除予約から6分待ち、過去の署名PUTが写真を復活させない。
- [ ] 空DBへバックアップを復元し、整理情報と画像を閲覧できる。
- [ ] 壊れたJSON、異なる所有者、未知バージョン、欠損オブジェクトを試す。
- [ ] 新端末で本人認証をして復元する。未送信写真は復元不可と確認する。

## 性能と費用
- [ ] 1,000/10,000/25,000枚で起動・グリッドスクロール・メモリをInstrumentsで測る。
- [ ] キャッシュ上限、古い画像の再取得、オフラインのキャッシュ済み表示を確認する。
- [ ] AWSの保存容量、PUT/GET、転送量を1週間測定し月額に換算する。

## 現在の制限
メタデータ1万件のホスト側測定はsessionsに記録済み。画像を伴う実機スクロール性能は未測定。

前景での逐次アップロードのみ。OSによる中断後は手動再試行で再開する。multipart/resumable-byte uploadは未実装（同じキーをファイル単位で再送）。原本上限100MB。Live Photoは静止画部分だけ。RAW・動画は未対応。ローカル保存は端末内にしかなく、再インストールや機種変更のバックアップにならない。大量一覧の実機測定、容量不足の実機再現、AWS結合検証は別途必要。
