# 共有お気に入り・検索・Macキャッシュ

## 操作
Macの左メニューとiPhoneの下部に「お気に入り」を配置。フォルダは一覧のハート（♡）、写真・動画・PDFはMacの一覧／ビューアの♡、iPhoneのビューアの♡または通常素材の長押しから登録・解除する。元の素材をコピーしない。お気に入り画面・フォルダ一覧を更新すると、他端末の変更を取得する。常時のプッシュ同期とオフライン編集は行わない。保存失敗ではハートを変更せず、再試行を案内する。

通常のお気に入りは現行の表示可能なカタログから名前・小画像を解決。PIN解除前の素材、ごみ箱内、完全削除済みの素材は表示しない。ごみ箱から復元すると残っていたお気に入りが再表示される。暗号化のお気に入りは隠したページを開き、同じ鍵でカタログを復号してから専用入口で表示する。iPhoneでは設定の「隠したフォルダを開く」で入口を表示し、「暗号化したお気に入り」で同じ端末PINを再確認する。鍵が違うものやカタログにない識別子は表示しない。

## 保存と競合
非公開S3の `media-hub/favorites/state.json` に、種類・root／鍵ID・カタログID・対象IDだけを保存する。名前・パス・画像・鍵は保存しない。通常素材の識別はrootと対象IDを基本とし、カタログ更新だけでは別のお気に入りにしない。暗号化は鍵・カタログ・対象の組で分離する。識別子自体が変わる別素材への自動引き継ぎはしない。

更新は1対象の追加／解除だけを受け付ける。S3のETag／条件付き新規作成で比較更新し、競合時は最大3回、最新情報へ同じ操作を適用し直す。別対象の同時更新を保持する。同じ対象の競合は最後に保存された操作を採用。3回失敗した場合は409で、成功扱いにしない。上限は10,000件・4MiB。壊れた状態を空の一覧で上書きしない。

iPhoneは既存JWTの本人確認の下でGET／POST `/favorites` のみ追加。素材のPUT／DELETE権限は付けない。Lambdaの書込権限はお気に入りの正確な1キーだけ。Macは既存AWSプロファイルで同じキーを読み書きする。通常の対象は現在のPIN認可とごみ箱除外を適用。暗号化対象は本人・暗号化カタログの存在を確認し、所属は端末側の復号カタログで検査する。識別子は既存暗号化一覧と同じく本人だけが取得できる。

## 画面保持と検索
Macは秘密領域を開いていない別アプリ切替で画面の識別・一覧・履歴を保持する。戻った後は背景で最新情報を確認。秘密領域が開いていれば即再ロックし、PINの付いたフォルダと全子孫、暗号化画面、選択中の閲覧・確認画面、秘密の検索／進行表示を除去する。通常の親フォルダは保持する。通常フォルダ画面全体を再生成しない。

Mac・iPhoneの通常フォルダとフォルダ内、暗号化のフォルダ内は名前検索・名前順／逆順・容量順に対応。Macの暗号化トップ一覧は名前を端末内で復号後に検索・並び替える。検索はその一覧内が対象で、全階層の全文索引を新設しない。フォルダ容量順は一覧内のフォルダ直下のファイル合計（トップ通常は既存集計）。撮影日情報がない素材へ推定日時は付けない。

## Macサムネイルキャッシュ
通常小画像のみ、256MiB上限。保存先は既存作業領域内の専用 `folder-uploads/thumbnail-cache`。ファイル名は保存先・オブジェクトキー・版・SHA-256から作るハッシュ。使用量カウンターを保持し、上限超過時だけ古い利用順に整理する。原本・復号済み暗号化小画像・アップロード待ちファイルは対象外。Mac「設定 → サムネイルキャッシュ」で使用量と上限を表示し、全キャッシュを削除できる。

毎回、PIN認可とごみ箱状態を確認してからキャッシュを使い、SHA-256一致を検査する。キャッシュ削除中に完了した古い取得で再保存しない。キャッシュの保存失敗は取得・照合済み画像の閲覧を妨げない。キャッシュは端末ごとのもので共有しない。削除は元ファイル・S3原本・お気に入りには影響しない。端末内への小画像保持を許可する今回の本人要望に基づく方針変更である。

## お気に入りの表示
Macは22pt、iPhoneは26ptの小さめのハート。登録済みはピンクの塗りつぶし。押せる範囲はMac30pt・iPhone44ptを確保する。登録済みデータ・端末共有方式は変更しない。
