# S3を正本にするMacアップロード・iPhone閲覧

2026-10-14。本人専用、非公開、追加費用月2,000円を目標。Macのみ手動アップロード。iPhoneはフォルダ・画像・動画の閲覧のみ。旧ローカルライブラリへの取り込み・同期・整理機能は通常UIから外す。既存データを勝手に削除・移行しない。

## 暗号化用の独立経路

通常とは別のMac手動アップロード・iPhone閲覧を追加。原本・小画像・管理情報を送信前に暗号化し、鍵は端末Keychainへ保管。パスワード付き復旧ファイルで引き継ぐ。既存の通常素材は自動移行しない。[手順と制約](ENCRYPTED-UPLOAD.md)。

## 構成と権限

- Mac: 既存AWS CLI短期認証で非公開S3へコピー送信。手動確認・開始・再試行のみ。入力元を削除しない。
- iPhone: Cognito Hosted UIのCode+PKCE、refresh tokenはKeychain。APIへ本人access tokenを送る。AWSの秘密鍵・CLI認証は渡さない。
- 新規閲覧API: API Gateway JWT検証＋Lambdaの本人sub照合。GETのみ。公開の自己登録は禁止。S3カタログに登録されたIDだけを読み、GET用署名URLを5分だけ発行する。
- Lambdaは既存S3のmedia-hubカタログ・原本・派生を読むだけ。Put/Delete権限なし。iPhoneにアップロード・編集・ごみ箱・原本保存操作はない。
- 原本はS3、Macの元フォルダは送信用入力。Mac表示はS3から取得して照合し、一時ファイルを応答完了・ビューア終了時に破棄する。原本の正本としてローカルを参照しない。
- 一覧は非公開S3の最大320px・50KB以下のサムネイルだけを取得し、原本は取得しない。Macで原本送信時に生成・送信、既存9件にも追加済み。カタログにthumbnailがなければアイコンを表示し、タップした画像だけ原本を取得する。端末の小画像は表示中のメモリだけで保持する。[詳細と既存素材への適用](MAC-SWIFTUI.md)。
- 画像は100MiBまで、サイズ／SHA-256照合後に表示。動画はAVPlayerのRange取得、自動再生なし。署名期限後のシーク等で止まった場合は「再生用の接続を更新」で新URLを得る。再生開始・GET回数だけで転送量は判断しない。
- URLはメモリ内のみ、APIレスポンス・S3 GETはprivate/no-store。画像データはiPhoneに原本ライブラリとして永続化しない。ログアウト／接続先変更で画面・トークン・表示状態を破棄する。

## 実装と検証の範囲

iOSの入口はCloudViewerRoot。旧LibraryModelを起動時に初期化しない。旧iOSの保存データは残すが新UIから操作しない。共通ReadRoot/ReadCatalog/ReadItem/ReadURLはcontractsから生成。Macの通常画面はCloudAppでS3フォルダ・アップロード・設定だけ。desktop APIは旧ローカル操作に410を返す。

閲覧APIは `backend/reader.py`、SAMは `infrastructure/reader.yaml`。Cognitoは `infrastructure/auth.yaml`（Lite）。認証スタックmedia-hub-authと閲覧スタックmedia-hub-readerを明示承認後に作成済み。現在のS3の公開ブロック・TLS・SSE-S3・バージョニングは維持する。旧ユーザーキー用の `backend/app.py` と別の専用ハンドラーで、既存カタログの名前空間だけ扱う。

東京にCognito Lite User Pool＋secretなし公開クライアント＋Hosted UI、HTTP API、128MiB ARM Lambda、読み取り専用IAM Role、保持7日CloudWatchログを明示承認後に作成した。既存S3のmedia-hubプレフィックスをGET／Listする権限だけ付与する。既存バケットの公開設定・暗号化・原本・自動削除規則は変更しない。Lambda配布コードを非公開S3へ置く場合は、そのコード成果物の送信もデプロイ承認に含める。個人メディアの新規送信・削除は対象外。

## iPhoneログインの継続（2026-10-14）
起動時にKeychainのrefresh tokenでaccess tokenを取得し、本人認証状態を復帰する。新しいaccess tokenはメモリだけ。本人ログインボタンも保存済みtokenを先に試し、保存なし・invalid_grantの期限切れ時だけブラウザ認証へ進む。通信・サービスの一時失敗で保存済みtokenを消さない。本人ログアウト／接続変更で削除。ユーザーパスワードは保存しない。フォルダ解除は復帰せず、5分／背景移行／閉じる時の再ロックを維持する。AWSのtoken有効期間は変更していない。

保存領域は従来と同じservice/account・AfterFirstUnlockThisDeviceOnly。保存更新はSecItemUpdate、新規だけSecItemAdd。端末更新は既存Keychainアクセスグループを継承。実機更新・起動済みで、自動復帰の画面確認は本人確認待ち。

## iPhoneの通常閲覧画面

「見る」は表紙付きフォルダを2列表示。表紙はフォルダ以下にある小画像付き写真の先頭、写真がなければ動画の小画像を使う。小画像なし／空ならフォルダアイコン。フォルダ内は子フォルダを表紙付きで表示し、写真・動画を3列の正方形で並べる。素材の名前・容量とフォルダタイトルは省略し、動画は再生マークで識別する。

素材をタップすると全画面で開く。左右スワイプで同じフォルダの前後へ移動。写真をタップすると閉じるボタンを隠す／再表示する。動画は閉じると接続更新を最小限に表示し、移動・終了で停止する。設定は別タブ、接続情報は折りたたむ。小画像は表示中のメモリだけで保持し、本人認証・PINと背景再ロックを維持する。

## iOSの閲覧キャッシュ

通常写真・サムネイルは端末のCachesへ最大1GB保存し、アクセスの古いものから削除する。OSによる削除もあるためオフライン保存の保証はない。キーは接続先・本人・カタログ・素材ID・原本SHA-256・画像用途から分離する。ログイン中かつ現在のセッションで取得済みのカタログに含まれる画像は、通信を待たずキャッシュを表示する。隠したフォルダは解除中だけ利用可能。カタログはメモリで再利用し、30秒以上経過後の再利用・一覧更新時に裏で更新する。更新はフォルダ単位にまとめ、画面へ反映する。APIの権限拒否・ロック設定変更・背景移行では表示とカタログを破棄する。通信失敗では取得済みデータを維持する。原本はディスクキャッシュから読む場合もSHA-256を照合する。ログアウト・接続先変更・設定の「キャッシュを削除」で破棄する。画像のメモリキャッシュは64MBを目安に制限し、再ロックで破棄する。暗号化内容の復号結果は従来通りメモリのみ。通常動画は署名URLによるストリーミングを継続する。


## iOSの通信回数と表示速度
通常画像はメモリ → 端末ディスク → 未取得分だけS3の順で表示する。ディスク読み書き・原本SHA-256照合・画像読み込み・1GB容量整理は専用actorで実行し、UIを待たせない。同じ画像の同時要求は1つの取得処理を共有する。キャッシュ削除の世代を照合し、削除前に開始した取得で保存を復活させない。

未キャッシュの通常サムネイルは、同じフォルダの最大60件単位で署名URLをまとめる。既存GET `/catalogs/{root}/{upload}?thumbnailIds=id1,id2` が、本人・現行の鍵設定・ごみ箱を確認し、全IDの所属と小画像を検査してから5分署名を返す。iOSでは取得中の要求を共有し、署名結果をメモリで240秒再利用する。URL一括取得だけでは画像本体を先読みしない。60枚なら署名APIとS3カタログ読取は各60回から各1回へ減る。画像本体の取得数・転送量はキャッシュ未取得の表示画像と、スワイプ中の下記先読み対象で決まる。

閲覧APIは毎秒20回・burst10、端末は60ms間隔で発行する。PIN解除は毎秒0.2回・burst1を維持。キャンセルされたタイルは将来の待ち枠を予約しない。通常動画と暗号化内容のディスク保存方針は変更しない。


## iPhoneライブラリの一覧とスワイプ（2026-10-15）
「見る」のヘッダーで「フォルダ／写真／動画」を切り替える。フォルダは3列の表紙付き一覧で、上部見出しは「ライブラリ」、フォルダ名はcaptionサイズ。下部メニューは「見る／スワイプ／設定」。写真一覧／動画一覧は本人に表示可能な通常カタログを横断し、MIMEで分類する。暗号化は解除後の「見る → 暗号化フォルダ」から閲覧し、横断一覧には混ぜない。

ヘッダーで写真／動画へ切り替えた時に既存カタログを再利用し、不足する管理情報を1フォルダずつ取得する。既存の30秒更新制限、小画像の一括署名と通常画像キャッシュを維持。読み込みが失敗した場合は部分一覧と再試行を表示する。スワイプは取得済みの表示可能素材を開始時にシャッフルし、1周内では同じカタログ素材を重複させず、上下操作と前／次ボタンで移動する。読み込み中は開始ボタンを無効化する。失敗したフォルダはその回の対象外。

スワイプでは現在の1件の読み込み後、現在位置より先の写真を最大10枚まで1枚ずつ先読みする。動画を除いた次の10枚が対象で、全件取得や末尾から先頭への循環はしない。移動時に古い先読みをキャンセルして範囲を更新し、終了・背景移行でも中断する。既存の通常画像キャッシュを共有し、保存済みの画像は再取得しない。動画は自動再生せず、離れた時／背景移行で停止する。AVPlayerが再生前に一部をバッファする可能性はある。追加DB・常時クラウド処理・履歴送信は設けない。素材はrootId／catalogId／itemIdの組で識別でき、今後の再生回数や閲覧時間の関連付けに使える。現段階では履歴・推薦・閲覧時間の永続保存は未実装。

## 先読みの容量制限（2026-10-15）

通常写真の先読みは次の写真最大10枚を候補とし、1枚10MiB以下・1窓合計20MiB以下に限定する。起動から再ロックまでの試行予定容量は累計100MiB。同じ画像は1回だけ試し、失敗・キャンセルでも予約容量を戻さない。大きい写真や予算超過の写真も本人が選んだ時には既存の100MiB上限まで表示できる。動画・PDFは先読みしない。既存キャッシュ・逐次取得・移動/終了/背景時の中断を維持する。累計は回線で実測した通信量でも月額の強制上限でもない。

通常iPhone動画はプレーヤーのアクセスログから取得できた受信量を5秒ごとと表示終了時に追加記録する。URLや名前を保存せず累積値の増分だけを集計する。暗号化動画は既存のURLSession計測のみとし二重に加算しない。通常動画の通信回数、OSが報告しない受信、終了後に到着する記録は未計測になり得る。AWS確定請求との一致は保証しない。

## 大きなフォルダ管理情報

管理JSONは16MiBまで。iPhoneは通常カタログの認可後JSONを1MiB断片で逐次取得し、SHA-256照合後にだけ一覧へ反映する。各要求でフォルダ認可とロック設定revisionを確認し、途中変更・再ロック時は未完成の一覧を破棄する。公開JSONの復元予算は追加フラグ分を含め20MiB、各断片はBase64形式。Lambdaの同期応答上限を超える一括返却はせず、旧クライアントには413を返す。Lambdaメモリは256MiBへ変更。暗号化一覧はS3 Range GETとメモリ復号を維持し、平文16MiBまで。素材とフォルダ各10,000件・送信合計20GiBは変更しない。

配布時は`backend/catalog_limits.py`を`reader.py`と同じLambda ZIPへ含める。同期応答の制約は[AWS公式のLambda上限](https://docs.aws.amazon.com/lambda/latest/dg/gettingstarted-limits.html)を参照。

## 指に追従するページ送り
通常・暗号化の横送りとランダム縦スワイプは、共通のUIKit UIPageViewControllerを利用する。指の移動量・速度・端の抵抗・取消を標準部品に任せ、スワイプ完了までは元のページを維持する。画像の拡大スクロールから瞬間切替用の独自スワイプ認識を外し、等倍ではページ送り、拡大中は画像パン、ピンチ中はページ送りを停止する。ページ送りのパンは1本指だけ。

表示ページの前後だけを保持し、ページ確定後に不要なページを除去する。隣ページは通常画像のメモリと保存済みディスクキャッシュを認可確認後に参照し、動画・PDFは先読みしない。暗号化写真は下記のメモリ限定先読みに分離する。通常の横送りでは現在画像の準備後に次の写真最大3枚を既存の容量予算内で先読み。縦スワイプは既存の最大10枚・20MiB窓・100MiBセッション予算を維持する。動画はページを離れると停止し、暗号化写真は現在／隣ページだけを容量内で保持し、暗号化PDFは非表示時に破棄。通常ページも大きな復号画像（20MiB超）は非表示時に破棄する。PDFの内部スクロールを優先し、前後の素材へは操作表示内の左右ボタンで移動する。「視差効果を減らす」ではボタンによる移動のアニメーションを省略する。

先読みと表示は同じ画像取得を共有する。先読み中の画像へスワイプした場合に二重取得しない。先読みの取消はその利用者だけを外し、表示中の利用者が残っている間は通信を中止しない。全利用者が離れたときに取得をキャンセルする。

画像はダブルタップで約2.5倍に拡大し、再度ダブルタップで等倍に戻す。ピンチ終了時は倍率のわずかな残り（等倍から2%以内）を等倍へ揃えてページ送りへ戻す。ピンチ／ページ移動中はホスティング表示を差し替えない。親のスクロールビュー全体は無効にせず、親のページ送り用パンだけを止めて画像の縮小操作を維持する。

通常画像はバックグラウンドで表示用に展開し、指で送る瞬間の画像展開を減らす。先読みは1枚の準備が終わるたびに隣ページへ反映し、残りの先読み完了を待たない。隣ページの保存済み画像確認では通信を開始しない。初回通信や容量上限外の画像では待ちが残る。

## 暗号化写真のメモリ先読み（2026-10-16）
写真表示後、直後の1件が5MiB以下の写真の場合だけ取得・復号する。動画・PDFを飛ばして遠くの写真を取らない。設定「暗号化写真をWi-Fiで先読み」は初期値ON。接続が確認できたWi-Fi／有線に限定し、携帯回線・従量扱いの接続・省データモード・接続不明では先読みしない。本人が選んだ現在画像は接続種別に関係なく従来どおり取得する。

暗号文ヘッダー60 bytesと1MiB単位のタグ16 bytesを含む予定容量を、再ロックまで累計50MiBで予約する。画面を開き直しても予約を戻さず、同一root/key/object/hashは1回だけ。失敗・取消でも返却しない。これは取得予定の論理上限で、HTTP再試行・通信の諸経費・他機能・月額請求を含む強制上限ではない。通常写真の100MiB予算とは別枠。

復号画像はPhoneSealedImageSessionに置き、ディスク・通常画像キャッシュ・URLCacheへ渡さない。現在／前／次の最大3件、展開後合計128MiB以下（現在→次→前の順）だけ保持。表示用画像は原本照合後、UI外で向きを適用して長辺4096px以下へ展開する。原本は変更しない。先読み中の写真を選んだ場合は同じ取得・復号タスクへ合流する。範囲外のタスクを取消し、破棄後の遅延結果は再登録させない。

閉じる・背景/非アクティブ化・再ロック/ログアウト・鍵変更で取消とメモリ参照の破棄。メモリ警告では現在画像を残し、隣ページを除去してその画面の先読みを停止する。復号済み画像の保存機能は追加しない。画面を開き直した画像は再取得することがある。

料金は先読みで見なかった写真と、メモリ破棄後の再取得分が増えうる。後で閲覧する同じ画像の取得・復号は共用する。1解除で50MiBを毎日1回予約した場合、30日で約1.5GiBが先読み枠の総量（純増量ではない）。解除回数が増えれば月間合計も増える。AWSは転送量と取得要求を課金対象としており、100GB/月のインターネット向け転送無料枠は他AWSサービス・リージョンと合算される。個別アカウントの無料適用・請求額は保証しない。[AWS料金](https://aws.amazon.com/s3/pricing/)・[課金の内訳](https://docs.aws.amazon.com/AmazonS3/latest/userguide/aws-billing-reports.html)。
