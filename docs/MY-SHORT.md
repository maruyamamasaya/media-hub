# マイショート

確認日: 2026-10-13（日本時間）

## Web・Windows
サイドバーの「マイショート」で開く。1素材を全体表示し、上下スワイプ・ホイール・↑↓・前へ/次へで移動する。ホイールは250msの無入力まで同じ操作として扱い、キーリピートは無視する。動画下端60pxはネイティブ再生コントロールのタッチ操作を優先する。実際のタッチ端末・マウス機種ごとの感度は追加確認が必要。

セッションは画面に入った時・条件変更・「新しい順で見る」で更新する。APIはseedとAsset IDのSHA-256による安定したランダム順を作り、20件ずつメタデータを取得する。履歴は画面のメモリだけで保持する。全件のバイト列取得・永続履歴・AI推薦は行わない。タグ1件とコレクション1件、サイドバーの保管場所を既存一覧条件で絞り込める。ごみ箱・削除中・アーカイブは除外する。セッションはDBの固定スナップショットではなく、途中で追加された素材はカーソル位置によって今回の対象に入らない場合がある。

お気に入り・コレクション追加は既存PATCHとrevisionを使用。詳細は既存画面を開く。画面から離れる、詳細・設定等を開く、document.hiddenになると動画を停止する。初期はミュート、再生・停止・音声は標準コントロールで操作する。空・読み込み・APIエラー・表示/再生エラーを表示する。

## Webの動画取り込みと派生
原本としてMP4・M4V・MOV・WebM・MKV・AVIを受け付ける。拡張子による保管対応であり、コンテナ内部・全コーデックの再生保証ではない。非空の未デコード動画も原本保管し、生成不能は派生のfailed状態で表示する。原本のハッシュ・容量・MIME・ファイル名、ffprobeが利用可能なら縦横サイズを記録する。再生時間・コーデックの専用メタデータは未実装。

FFmpegがPATHにある場合、512px以内JPEGサムネイルと1280px以内・H.264/AAC・MP4のdisplayを生成する。AV1/HEVC等の入力は導入したFFmpegのデコーダに依存する。変換は各180秒で打ち切る。同期処理なので取り込み完了まで待つ。FFmpegの自動導入・同梱はしない。API/Windowsアプリを起動する環境にFFmpegを用意し、APIを再起動後、詳細の「プレビューを再生成」で再試行する。

未導入・非対応コーデック・破損・時間切れでも原本はreadyのまま保持し、サムネイル/displayをfailedにする。一覧はサムネイルのみ、マイショート/動画詳細はdisplayのみを取得し、動画原本へ自動フォールバックしない。原本取得・ZIP・転送は従来の明示操作を使う。上限100MBは既存設定を維持する。未知の拡張子は取り込み失敗とし、入力元は変更しない。

## iOS（旧Photoライブラリ）
写真タブを維持し、「マイショート」タブを追加。IDをセッションごとにshuffleし、上下スワイプと前へ/次へで移動する。350ms以内の連続移動を抑止する。表示対象は削除中以外、アルバムで絞り込める。お気に入り・アルバム所属・詳細は既存LibraryModelへ接続する。旧モデルにはタグ・アーカイブ・ごみ箱がないため、これらはWeb共通API接続後の工程。

PhotosPickerは画像と動画を選択可能。PhotoKitの.photo/.video原本を無加工で書き出し、動画はAVFoundationで512pxポスターと720pプリセットの再生用MP4を別生成する。写真ライブラリにあるMOV/MP4等のうちOSがデコード・MP4へ書き出しできる動画が再生対象。全形式保証はしない。生成失敗もPhotoと原本を保存し、再生不能を表示する。原本の写真ライブラリへの保存は明示操作で.videoを使用する。写真ライブラリの削除APIは使わない。

動画は表示中・scenePhase.activeの時のみAVPlayerで再生し、詳細・タブ移動・背景移行時に停止する。初期ミュート、再生/停止/音声と失敗時の再試行を表示する。プレイヤーは原本を参照せずplayback.mp4を使用する。

開発用LocalObjectStoreには既存3ファイルに加えてplaybackキーを照合保管し、既存JSONバックアップ/復元・削除でも保持/整理する。復元後は再生用ファイルだけを必要時に取得する。旧AWS署名契約は静止画専用なので、新規動画のAWS転送を拒否し、原本と派生を端末内に保持する。変換失敗など未送信素材を含む場合は従来どおり正常バックアップ完了条件を満たさない。AWSへの実接続・デプロイは行っていない。

## 保管とキャッシュ
Web/APIは既存File ID/content境界とCache-Control: no-storeを維持する。追加した素材用localStorage・Service Worker・全素材の先読みはない。履歴と表示中の画像/動画のブラウザ管理バッファは画面・タブの終了で解放されるが、OS/ブラウザの内部バッファの確実な消去期限をアプリは保証しない。API側の派生はライブラリの永続ファイルで、素材の完全削除で原本と一緒に整理する。

iOSの既存DiskCacheは512MB上限の最終使用順、日数TTLなし。再生用取得ファイルも同じrootに保存し、設定の「キャッシュを削除」で削除できる。表示中のプレイヤーバッファは停止・破棄する。Pendingの原本・新規動画の再生用MP4は未送信保管データで、キャッシュ削除対象にしない。原本解放は従来のAWS照合ゲートを維持し、今回のローカル動画を自動削除しない。

将来は認証された非公開S3のFile別短時間URL、再生用動画の署名契約、iOSとAsset APIの同期、端末キャッシュTTL・ログアウト時消去・原本の明示取得後の整理・再生中ファイルの削除保護が必要。今回のローカル動作をその完了とみなさない。
