# iOSフォルダ同期

2026-10-12。AWSを保留し、MyMusicと同様に「ファイル」からユーザー選択フォルダを参照する方式を優先する。

## 操作
1. 設定 → フォルダ同期 → フォルダを追加。
2. 「ファイル」の選択画面でiCloud DriveまたはこのiPhone内の画像フォルダを選ぶ。
3. 登録時に同期し、写真一覧へ表示する。以降の追加・改名・移動は設定の「同期する」で反映。
4. フォルダ移動・アクセス切れは、既存登録先の「フォルダを選び直す」で再接続する。

サブフォルダを含むJPEG／PNG／HEIC系の静止画を対象とする。新規登録は1回100件。既登録の一致画像は上限を消費しない。隠しファイル・パッケージとフォルダ外への参照は読み込まない。

## 原本と整理情報
原本は選択したフォルダに保持し、アプリには画像情報と必要な派生キャッシュだけを保存する。アクセス情報は端末内のbookmark、所在はRoot UUIDと相対パス。SQLiteをiCloud Drive上で直接開かない。

SHA-256が一致する画像の改名・移動では素材UUID・お気に入り・アルバム所属を維持する。同じパスの内容変更は以前の画像情報を上書きせず通知。欠損も登録を残して通知する。再配置・再同期で復旧できる。フォルダ全体の読み取りに失敗した場合は欠損と断定しない。

参照画像のアプリ内削除は登録・整理情報・キャッシュだけを削除し、フォルダの原本は残す。再同期で新しく登録される。写真ライブラリへの原本保存は、一時コピーのハッシュを確認してから行う。

## iCloudと現在の制限
iCloudの未ダウンロード原本は取得を要求し、取得待ち件数を表示する。時間を置いて手動再同期する。常時監視・バックグラウンド同期は未実装。

別の端末でも同じiCloud Driveフォルダを選んで画像を参照できるが、アプリの素材UUID・お気に入り・アルバムは端末固有。Web版とのカタログ同期も未接続。同じ内容の複数所在は統合せず、最初の登録元を優先する。

フォルダ参照を含むライブラリのJSONバックアップは未対応のため明示的に停止する。原本はフォルダに残るが、アプリ再インストールで整理情報とbookmarkは失われる。既存の写真取り込み専用ライブラリのバックアップは従来どおり。

撮影日は現段階ではファイル作成日。派生は既存iOSと同様にJPEG。EXIF撮影日時・透過派生対応は別工程。

## 実機での確認
- 設定から実際のiCloud Driveフォルダを選び、一覧・詳細に表示できる。
- アプリ終了・再起動後もフォルダへアクセスし、同期・画像表示できる。
- 未取得画像の取得待ち → 再同期、オフラインでのキャッシュ表示を確認する。
- 改名・移動後もお気に入りとアルバムが残り、変更・欠損は通知される。
- フォルダ再指定後に復旧し、アプリ内削除でも原本が残る。

実iCloud DriveのFile Provider動作はシミュレータ内ローカルフォルダの自動テストでは確認できない。
