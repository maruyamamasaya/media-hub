# ローカルWebの起動と運用

Windows、Node.js 22.12以上または24、Python 3.12以上を用意する。確認環境はNode 24.19、Python 3.12。初回はリポジトリルートのPowerShellで実行する。

```powershell
.\scripts\setup-web.ps1
.\scripts\start-web.ps1
```

PythonがPATHにない場合はsetupに `-Python 'C:\path\to\python.exe'` を渡す。Codexの今回の環境では通常のPython登録が壊れていたため、内蔵ランタイムを指定した。setupは仮想環境と依存を準備し、生成契約とテスト素材を作る。Python本体にpipが必要。venvのpipがないポータブルPythonでも、Python本体のpipから対象venvへインストールできる。

`http://127.0.0.1:8765` をブラウザで開く。startはWebビルド後にAPIとWebを同じoriginで配信する。Ctrl+Cで停止。端末内専用で、LANやiPhoneからのアクセスはまだ対象外。

## 保存先と追加
`.local/asset-library/library.sqlite3` がDB、`objects/` が原本・派生、`staging/` が追加中と保存失敗の原本。入力は `.local/fixtures/`。生成サンプル12件は個人写真ではない。画面の「テスト素材を取り込む」または設定からコピーして登録する。

任意の個人フォルダは自動探索しない。自分のJPEG/PNG/WebP/HEIC・MP4/MOV/WebM/MKV/AVI/M4Vはファイル選択・ドラッグ＆ドロップで追加できる。原本100MB、1リクエスト500MB、APIバッチ100件上限。Webはファイルごとに送信する。HEICはコンテナ判別だけで、画素デコード・プレビューは未対応。EXIF撮影日時の抽出は未実装、写真種別は詳細で指定する。

## 開発時
APIとUIを別の端末で起動する。
```powershell
.venv\Scripts\python.exe local-api/run.py
```
```powershell
cd web
npm.cmd run dev
```
開発UIは `http://127.0.0.1:5173`。APIへのリクエストはViteのproxyを通る。8765と5173は固定で、使用済みなら既存プロセスを確認してから対象アプリを止める。

## 通常とアーカイブ
サイドバーの「通常の素材」「アーカイブ」で切り替える。詳細から個別に、複数選択から最大100点をまとめてアーカイブ／通常へ戻せる。コレクション画面の「全体をアーカイブ」「全体を通常に戻す」は、表示ページやフィルターと無関係に全所属素材を対象とする。確認画面で対象件数と他のコレクションへの影響を示す。ごみ箱の素材は対象外。

検索・お気に入り・コレクションは「保管状態」で通常／アーカイブ／両方を指定できる。タグ・所属・お気に入りは保持され、原本取得でも状態は変わらない。ごみ箱から復元すると元の保管状態へ戻る。新規追加は通常状態で、コレクション全体の操作後に追加した素材を自動アーカイブしない。

現時点はローカルDBの分類機能。原本・派生の配置と使用容量は変わらず、AWSの費用削減は発生しない。起動時に既存DBをversion 3へ自動移行する。移行前に既存のバックアップ手順で退避できる。旧プログラムへのDB逆移行は提供しない。

## バックアップと復元
画面の追加・更新処理が終わったことを確認し、APIをCtrl+Cで停止する。SQLiteだけでなく `.local/asset-library/` 全体を別の保存先へコピーする。WAL/SHMが残る場合も同じフォルダの一部として扱う。起動中の単純コピーは避ける。

復元も停止中に行う。現在の保存フォルダを先に退避し、バックアップ全体を `.local/asset-library/` として配置する。再起動して素材数と原本ダウンロードを確認する。別PCでは依存とプログラムを準備してから同じ手順を使う。JSONだけのバックアップは新Web版では提供していない。

## 再試行と制限
- 保存失敗は追加結果から再試行。形式不正・途中の受信失敗はファイルを再選択する。
- 派生失敗は詳細の「プレビューを再生成」。HEICはデコーダー未導入のため再試行でも表示されない。
- 変更競合は詳細から最新情報を再読み込みして編集し直す。
- 欠損ファイルは表示エラーとし、素材情報を勝手に削除しない。
- 完全削除の途中失敗はdeletingが残り、再起動または詳細から再試行する。
- ごみ箱は自動削除しない。完全削除後は元の入力ファイルまたはバックアップから再登録する。
- テストフォルダ取り込みは同期実行で、巨大なフォルダでは結果表示まで待つ。常時監視はない。

データと仮想環境・node_modules・distはGit除外。クラウド・公開認証・多端末同期は未接続。既存iOSの保存領域と新Webの保存領域は独立。

## ローカル／開発用リモートの確認
設定にローカル画像フォルダの実パスを表示する。そのフォルダへJPEG/PNG/WebP/HEICを配置し「ローカルフォルダを読み込む」。一覧の所在バッジと「フィルターと並び替え」→「保管場所」で確認する。登録元の画像は通常ファイルのまま参照する。移動・編集の自動追跡は未実装。参照素材の削除は参照元を残す。
新規選択追加は同フォルダへコピー。既存原本は開発用リモートとして表示するが、実体はPC内に保持。S3・端末間共有・リモート転送による容量解放は未接続。[保管設計](STORAGE-DESIGN.md)を参照。

設定の「フォルダ同期」で画像フォルダを指定し「同期する」。Windowsアプリでは「フォルダを選ぶ」でOSの選択画面を開く。Webでは絶対パスを入力する。移動後は同じ登録先を選び、新しい場所を指定して同期する。一致・新規・改名移動・変更・欠損の結果を表示する。原本は参照し、アプリ管理領域と重なる外部同期先は受け付けない。
素材詳細の歯車から模擬アップロード／ローカルダウンロード。アップロード確認後は参照元も照合して削除する。整理が失敗した場合は同じ設定から再試行。リモート実体はPC内で、AWS送信はない。
バックアップには参照先の外部フォルダも必要。アプリDBだけの退避では外部原本は復元できない。

設定はリンク一覧。「フォルダ同期」「保管場所と使用量」「バックアップ」「テスト用素材」は専用ページで操作し、「設定に戻る」でリンク一覧へ戻れる。
